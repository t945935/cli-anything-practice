# 教材任務交付範本

請用真實結果替換括號內容；失敗時也使用此格式。回報可直接寫在 Agent 對話中，避免另建未指定的檔案。

任務結果：（基本檢查通過，待人工檢視／建置失敗／檢查失敗／檢查未完成／未開始；請選擇符合證據的描述。）

## 來源與工作

- 原始來源：（路徑）
- 本次輸入快照：（路徑；未建立則寫未建立）
- state.json：（路徑與實際 status）
- 使用的嘗試：（例如 attempt-001；未開始則寫未開始）

## 命令結果

| 步驟 | 實際結束碼 | 證據與說明 |
| --- | --- | --- |
| doctor | （填寫） | （JSON 的 ok 或 error） |
| check | （填寫） | （資料檢查結果） |
| plan | （填寫） | （輸出計畫） |
| start | （填寫） | （state 與命令紀錄位置） |
| audit | （填寫） | （新報告位置、passed／failed／blocked 數量） |

未執行的步驟請寫「未執行」及原因，不填預期結束碼代替實際結果。

## 成品與待確認事項

- 簡報與講義：（實際存在的檔案位置）
- 圖片：（位置，註明獨立素材）
- 新預覽：（位置）
- 已完成的視覺檢查：（具體檔案與檢查項目，或未檢查）
- 尚待確認：（版面、內容、目標軟體顯示等）
- 異常與下一步：（原因與建議；未取得任務範圍內的授權前，不宣稱已修復）

`needs_review`、`passed_basic_checks` 與「可以出版」是不同的判斷；不得互相替代。
